# 디자인 개선사항

코드 분석(2026-11-23) 기반. 실제 화면은 아직 확인하지 않았으므로 색감·분위기·레이아웃 판단은 "보류" 항목으로 남긴다.

진행 순서: **A (작은 수정) → B (기준 설계) → C (화면별 적용) + D (인터랙션)**

공통 규칙
- 기능 동작은 바꾸지 않는다. 화면·스타일·인터랙션만 변경한다.
- 각 작업 후 `npm run check` 통과가 완료 기준이다.
- 이 문서에 없는 디자인 결정이 필요하면 임의로 정하지 말고 보고한다.

### D2 현황 (`src/pages/Room.jsx:2258`)

이미 구현됨: 바닥에서 60px 이상 떨어져 있을 때 상대 메시지가 오면 "새 대화" 버튼 표시, 누르면 맨 아래로 이동 + 읽음 처리, 직접 스크롤로 바닥에 닿으면 사라짐.

다듬을 점:
- 화살표 아이콘 색 `#fff` 고정 → 라이트 테마에서 안 보임 (테마 색 사용)
- `<div onClick>` → `<button>` (키보드·스크린리더 접근)
- 위치 `bottom: 110` 고정 → A2(입력창 자동 높이) 적용 시 입력창과 겹칠 수 있음
- 선택: 쌓인 메시지 수 표시 ("새 대화 3", 99+ 상한), 나타날 때 짧은 등장 애니메이션

### D3 설명

현재 앱 진입, 방 목록, 채팅방, 캐릭터 화면이 모두 데이터를 받을 때까지 전체 화면 `LoadingScreen`을 보여준다. 스켈레톤은 그 대신 실제 화면의 뼈대(헤더, 카드·말풍선 자리)를 회색 블록으로 먼저 그리고 데이터가 오면 채우는 방식이다.
- 효과: 실제 속도는 같아도 체감 대기가 짧고, 로딩 → 화면 전환 시 레이아웃이 튀지 않음
- 범위: 방 목록(카드 3~5개), 채팅방(말풍선 좌우 교차 5~6개), 캐릭터 목록
- 앱 첫 진입(인증 확인)은 기존 `LoadingScreen` 유지
- 은은한 반짝임 애니메이션, reduced-motion 시 정지

지양: 화면 전환마다 큰 애니메이션, 과거 메시지 등장 효과, 300ms 넘는 UI 반응(연출 제외).
